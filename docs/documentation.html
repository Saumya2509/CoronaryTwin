CoronaryTwin

A 3D coronary "twin" that shows where risk sits (overall CAD and the LAD, LCX and RCA arteries), how sure the model is, why it thinks so, and what would change it, from 51 routine clinical measurements.

Decision support and educational use only. Not a diagnosis and not a substitute for formal diagnostic imaging or clinical judgment. The 3D coloring is schematic: it comes from vessel-level estimates, not lesion locations.

What makes it different

  • Uncertainty you can see: calibrated probabilities, conformal "Uncertain" states, and a sub-model range on every estimate.
  • Explanations on the anatomy: SHAP per artery, a waterfall that adds up exactly, and glows on the heart linked to the chart.
  • Clinically shaped tools: next best test (which missing value matters most), similar historical cases, out-of-distribution warning, cohort view.
  • Honest by construction: safety banner in every view, captions generated from the patient's own numbers, and the limits stated in the app.

1 · Data, preprocessing and the leakage guard

Dataset: Extension of Z-Alizadeh Sani (UCI id 411, DOI 10.24432/C5461K). 303 catheterized patients from one center, 59 columns, no missing values.

TargetDefinitionPositive
CADOverall coronary artery disease (Cath)71.3%
LADLeft anterior descending ≥ 50% stenosis58.4%
LCXLeft circumflex ≥ 50% stenosis39.3%
RCARight coronary artery ≥ 50% stenosis37.6%

Inputs: 51 features in 7 explanation groups: Demographics, History, Symptoms, Vitals, Labs, ECG and Echo. Excluded with reasons: the four label columns, Weight and Length (BMI is computed exactly from them), Obesity (equals BMI > 25) and Exertional CP (constant).

Feature registry: one source of truth

features.yaml holds each input's name, source column, encoding, group, valid and normal range, whether it is modifiable, and patient wording. It generates the API's input validation, the form, the SHAP groups, the what-if sliders and the patient text. A new feature needs no code change, and a test proves it.

Leakage guard

  • Model inputs are built from a whitelist (the registry), and a blacklist blocks every label column. test_leakage.py fails if one reaches fit.
  • All preprocessing (imputation, scaling, one-hot) is an unfitted pipeline that is fitted inside each training fold only.
  • Audit: no single input has a ROC-AUC near 1.0 (highest: typical chest pain, 0.80). Overall CAD equals "any stenotic vessel" for 302 of 303 patients, which is consistent.

2 · Models and validation

  • Four families per target (logistic regression, random forest, XGBoost, LightGBM), tuned inside an inner 3-fold search and scored on an outer 5-fold × 5-repeat split. The simplest family within one standard error of the best is kept.
  • Calibration: Platt scaling with 5 cross-fitted copies; their spread gives the sub-model range shown for every estimate (model disagreement, not a CI).
  • Conformal prediction at α = 0.10 turns each probability into Likely / Unlikely / Uncertain, with coverage checked on held-out folds.
  • Thresholds favor recall (≥ 0.85), because a missed narrowing costs more than a false alarm.

4 · Explainability

  • SHAP per artery: each of the four models has its own explanation (LinearExplainer or TreeExplainer). Selecting the LAD shows LAD drivers.
  • Waterfall: from the average patient to this patient's model score, one bar per measurement group, in the model's own units so it adds up exactly. Hovering a group lights up its glow or gauge on the 3D heart.
  • Stability: feature rankings across 5 refits agree with Spearman ρ 0.78–0.92.
  • LIME cross-check: on 20 patients per model, LIME and SHAP share 60–70% of their top-3 drivers (chance about 6%).
  • Two audiences: a clinician view with values and units, and a plain-language patient view with summary cards.

5 · 3D visualization

  • Procedural anatomy, no third-party meshes: one analytic surface with ventricles, atria and appendages, and grooves fitted to the artery paths. Arteries are projected exactly onto it, so they never float off the heart (tested). Muscle, epicardial fat, the great vessels and a wet sheen are generated in code.
  • Encoding: color = calibrated probability on a yellow → rose ramp used only for risk (luminance falls monotonically, tested). Uncertainty = translucency, a dashed outline and a slow, irregular pulse. Color is always paired with a number and a word.
  • Interaction: rotate, zoom, presets, click an artery (the camera flies in and a detail panel opens with its drivers and a what-if slider), ghost heart, explanation overlays, cohort averages, and Present mode, a captioned walkthrough generated from the patient's numbers.
  • Performance: about 110k triangles, renders on demand. Measured on Intel HD Graphics 620 (integrated): 36–44 fps with all effects, 60 fps in Lite mode, which switches on automatically below 14 fps. A 2D SVG fallback covers browsers without WebGL.

6 · Integration, running it, limits and credits

Run it

  • Docker: docker compose up --build → http://localhost:8080 (API docs at :8000/docs).
  • Local: python tasks.py setup, python tasks.py serve, python tasks.py web.
  • Try it: Watch the 90-second tour on the landing page, or upload a file from csv/ (50 synthetic samples, single and cohort).
  • Rebuild everything: data → train → explain → experiments; seeds are fixed, so numbers reproduce.

Engineering

  • 120 Python tests (leakage, API contract, SHAP additivity, registries, specialities) and 84 web tests, plus an end-to-end browser test of the judge path.
  • CI: registry check, tests, web build, both Docker images, a smoke test through nginx, and the end-to-end test.
  • Registries (features.yaml, registry.json, anatomy.json) are cross-checked; a new feature, model or artery is a registry edit.
  • Privacy: patient inputs and IDs are never stored; a SQLite log keeps anonymous outputs only (view_db.py).

Safety layers

  • Persistent banner in every view, in Present mode and in the exported PDF; first-use acknowledgement.
  • "Disclaimer" field in every API response; wording says "estimated" and "likely", never "diagnosed".
  • Schematic tag on the 3D stage; captions never say more than the numbers.

Limitations

  • 303 patients from a single center; no external validation. The original and extended Z-Alizadeh Sani files contain the same patients.
  • Labels are per vessel (≥ 50% stenosis), not per lesion: the 3D coloring cannot show where a narrowing is.
  • Explanations describe associations the model learned, not biological cause; what-if is model sensitivity, not treatment advice.
  • LCX and RCA discrimination is moderate (AUC ≈ 0.72).

Future work

  • External validation on an independent cohort; a browser-only (ONNX) inference mode; a reviewed regional-language patient view.
